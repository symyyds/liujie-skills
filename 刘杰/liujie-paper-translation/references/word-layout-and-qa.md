# Word 样式与逐页验收

## 样式基线

这套基线来自实际完成并检查过的中文论文讨论稿。它是可调整的默认值，不是对所有期刊或所有语言的强制规范。用户模板和明确要求优先；不要为了匹配示例页数而减字号或删内容。

| 元素 | 默认值 |
| --- | --- |
| 纸张 | Letter，8.5 × 11 英寸，纵向；支持改 A4 |
| 页边距 | 上 0.72、下 0.70、左右各 0.80 英寸 |
| 正文 | 宋体中文，Times New Roman 英文，11 pt，黑色 |
| 段落 | 1.18 倍行距，段后 5 pt，两端对齐，无强制首行缩进 |
| 中文题目 | Title 样式，18 pt，居中，黑体中文；自然换行 |
| 英文原题 | 10 pt，居中；原文没有时不编造 |
| 一级/二级/三级标题 | 14 / 12 / 11 pt，黑色，中文黑体，保留原编号 |
| 标题间距 | 段前 10 pt，段后 5 pt，与下一段同页 |
| 图题/表题 | Caption 样式，10 pt，居中；长说明可左对齐 |
| 图内术语说明 | 9–10 pt，图题之后，保持可读；内容多时换行 |
| 表格 | 浅蓝表头 EAF0F5、浅灰边框 D9D9D9、重复表头、自适应行高 |
| 参考文献 | 约 9 pt，1.08 倍行距，段后 4 pt，保留检索信息 |
| 页脚 | 简单居中页码，9 pt；无需装饰页眉 |

不加标题下横线、彩色装饰标题、卡片框或大面积底色。使用 Word 样式而非手工空格做对齐；设置东亚与西文字体两套属性，避免中文字体失效。若环境缺少宋体/黑体，选择实际存在的可读 CJK 字体并告知替代，不把缺字方块当作正常结果。

## 图表与分页

图按原始宽高比插入，不能超过正文宽度。先保证坐标、图例与细线可辨，再决定物理尺寸。图像与图题相邻，表题在表格之前；尽量靠近首次引用，不把所有图表堆到文末。

表格设置实际列宽，术语/方法列通常比纯数值列宽。允许内容换行，避免用固定行高裁切文字。先调整列宽、行间距和横向/纵向分节，再考虑小幅减字号。宽表不应强行塞入不可读的 6 pt 字体。

跨页长表重复表头，保持列序和列宽；短行可禁止拆行，单行长到超过页面时不能一律禁止。不要把所有表格行都设为“与下段同页”，否则可能把整表推走并制造大段空白。不要用几十个空行手动换页。

短图题尽量和图同页；极长图题、超过一页的表注允许合理续页，不以“永不拆分”牺牲可读性。文中的图表号和实际对象应一一对应，包括附录编号与分面板字母。

## 公式路径

随包 builder 的 `$...$` 是内部输入标记，不得原样出现在交付文档。转换走 LaTeX → MathML → OMML，所需 Microsoft `MML2OMML.XSL` 由已安装的 Office 提供，或由调用者显式指定；技能包不分发此微软文件。

转换失败时停止该次构建并报告公式位置，不把 LaTeX 直接塞进 Word，也不自动改成图片。原图公式必须由输入明确提供 image，且用户没有要求全部可编辑；带编号的截图不要再次追加同一编号。构建记录应区分原生公式和图片公式。

无论使用哪条路径，都逐个对照原文检查上下标、正负号、分式、括号、求和上下限、向量/矩阵、字体与编号。渲染正常不证明数学表达等价。

## 渲染与验收

使用获准运行时。Codex 提供 Documents 技能时，先运行其要求的创建/编辑登记，再按其 `render_docx.py` 流程生成页图。优先使用捆绑 LibreOffice，不能退而调用用户桌面 LibreOffice。

Windows 只有 Word 时可使用：

```text
python scripts/render_word.py draft.docx --output-dir work/render
```

需要复用 Documents 的栅格化步骤时：

```text
python scripts/render_word.py draft.docx --output-dir work/render --renderer /path/to/documents/render_docx.py
```

该辅助脚本只读打开输入、关闭宏，用独立 Word 实例导出，不关闭用户已打开的 Word。需要本机 Microsoft Word 和 pywin32；没有 Word 时不能使用。`--renderer` 为本环境经确认的工具路径，不写死插件版本。图像审阅依然由使用技能的代理完成，脚本不自动证明版面通过。

每页按实际阅读比例检查：标题层级与黑色字体、中文缺字、正文行距、孤行、图像比例、图内标注、图题配对、表头重复、单元格数值位置、公式完整性、参考文献、页脚。不能只看首页或联系表缩略图。对最终版本重新渲染；如果用页图哈希证明页面未变，也应明确保留已审阅版本对应关系。

验收记录放在 work 中，记录源文件版本、输出文件哈希、页数、结构检查、数值警告处理、视觉检查日期与未解决问题。最终不把日志写进论文正文。

## 有限环境下的诚实交付

- 缺失源内容：说明范围和缺失位置，不把节选称为全文。
- 缺少原生公式转换器：说明可选方案，未经同意不降级用户要求的可编辑公式。
- 无法渲染：可以保留文件并交付为未视觉验证稿，清楚声明限制，不能标记为“逐页验收通过”。
- 特殊格式超出随包 builder：在工作副本扩展脚本或使用成熟文档工具，再做同样的结构与渲染检查；不要丢弃这些内容。
