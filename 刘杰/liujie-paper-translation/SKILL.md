# 刘杰-论文翻译.skill

把论文变成可以和导师、合作者逐段讨论的中文稿。保留原文的论证顺序与信息密度，让中文自然、术语稳定、图表可查，而不是把论文压缩成解读或另写一篇文章。

## 交付约定

- 默认交付完整中文 `.docx`；多篇论文分别生成。保留英文原题，正文以中文为主。只有用户要求时才制作双语对照、译注汇编、PDF 或摘要。
- 以用户指定的版本为唯一翻译依据。旧版本、网页摘要或领域常识不能悄悄补进译文。缺页、无法读取的内容或影响意义的歧义需要明确说明。
- 正文、标题、表格用可编辑 Word 内容。公式优先使用经验证的原生 Office Math；复杂公式在未要求可编辑时可保留清晰原图，但必须说明哪些公式是图片。
- 不擅自改变研究结论、添加引文、补做实验或把作者的弱结论加强。翻译与修改建议分开。
- 复用本技能的方法与样式，不复用其他论文的正文、作者信息、投稿编号或项目路径。

## 1 确定来源和建立覆盖清单

先说明本次采用的来源、语言和交付格式。用户已给出明确文件时直接执行，不重复询问已知信息。

阅读 [references/translation-and-logic.md](references/translation-and-logic.md)，然后：

1. 核对文件、版本、页数和可提取文字情况，梳理标题、摘要、关键词、章节、脚注、图表、公式、附录、致谢和参考文献。
2. 按真实阅读顺序建立源块清单。PDF 的换行不等于段落；双栏、跨页段落、侧栏和脚注必须对照页面确认。不要按固定纵坐标批量删除“页眉”：页顶可能是真实正文或表题。
3. 给每个源块稳定 ID 和来源位置；正文可以记录页码与边界框，Word 可以记录段落/表格位置。所有省略都记录理由，只排除确认的重复页眉、页码等非内容项。
4. 建立项目术语表，区分近义但不等价的概念。决定首次出现时是否保留英文/缩写，以后保持一致。

正文、图表资产可按章节并行处理，但先共享术语表与块 ID 规则。合并后必须统一术语、编号和跨章节指代。

## 2 按论证关系翻译

以原始逻辑段落为基本单位，完成三遍检查：

- **忠实翻译**：保留主语、动作、对象、条件、比较基线、数字与单位、否定、范围和不确定性。长句可拆成自然的中文句子，不能为顺口改变因果。
- **衔接复核**：确认段落承担的是背景、问题、方法、证据、对比、解释还是限制；核对代词与“这一区别”等指代。连接词必须有原文依据，不机械给每段添加“因此”“此外”。
- **回看原文**：逐块检查是否遗漏从句、例外、边界条件或反例。尤其检查“未发现显著差异”与“没有差异”、“相关”与“导致”、“在本设置下”与普遍结论。

默认保留段落边界及顺序。确需拆分过长段落时保留可追溯映射；不得把分散论据拼成作者未提出的新结论。源文中的疑点在内部疑点表或独立说明中标记，不能偷偷修正，也不能把解读混进译文。

## 3 图表公式与 Word 成稿

生成前阅读 [references/word-layout-and-qa.md](references/word-layout-and-qa.md)。有用户模板时以模板为准；否则使用本技能从已验证中文讨论稿中提炼的朴素学术样式。

- 图保留原图的数据、坐标、图例和面板；中文图题放在图下，必要时附“图中术语”对照。不要通过重绘或覆盖英文破坏信息。
- 表重建成可编辑表格，保留行列、数值、单位、显著性标记、加粗含义及脚注；中文表题放在表上。逐单元格核对，不只比较数字集合。
- 保持公式符号、上下标、括号、运算符、编号和适用范围。原生 OMML 与图片公式分开登记，不把图片声称为可编辑公式。
- 保持章节、图、表、公式和引用编号。参考文献的作者、原题、期刊、卷页、DOI 等通常保留原文，方便检索；完整保留，不以“见原文”代替。

可使用随包脚本，先读 [references/data-contract.md](references/data-contract.md)：

```text
python scripts/audit_translation.py work/translation.json --output work/audit.json
python scripts/build_docx.py work/translation.json --output outputs/中文译稿.docx
```

`python` 表示当前环境已解析的可用 Python 路径。在 Codex 桌面内，优先使用 `load_workspace_dependencies` 返回的运行时；缺依赖时说明情况，不默默安装或改全局环境。脚本不负责自动翻译，不替代语义检查；特殊表格、复杂版式可以在工作副本中扩展。

## 4 三层交付检查

1. **覆盖与结构**：源块全部映射或明确排除；章节、脚注、图表、公式、附录和参考文献数量可解释；编号及交叉引用一致。覆盖审计只能证明已登记源块被处理，不能证明 PDF 提取没有漏字。
2. **语义与数值**：对照原文检查全部译文，复核术语、条件、否定、比较基线和结论强度；逐格核对表格，逐个核对公式。自动数字检查输出的是待复核线索，不能单独判定翻译正确。
3. **视觉**：将最终 DOCX 渲染成逐页 PNG，查看每一页，修正表头跨页、孤立标题、图题分离、公式裁切、文字缺字、过小字号和异常留白。修改后重新渲染受影响文档；旧版截图不证明新版合格。

如果环境提供 Documents 技能，按其工作流使用 `render_docx.py`。Windows 无捆绑 LibreOffice 但有 Microsoft Word 时，可用随包 `scripts/render_word.py`；可通过 `--renderer` 接入现有 Documents 渲染器。不要改用用户的桌面 LibreOffice 绕过捆绑运行时要求。其他环境可以使用其获准的文档渲染器。

没有可用渲染器时保留 DOCX，明确告知“尚未完成逐页视觉验证”，不能声称排版已验收。不得要求通过删除内容、极小字号或任意压缩页面来满足不存在的页数目标。

## 交付时说明

给出 Word 下载链接和简短说明：覆盖范围、是否保留原图、正文/表格/公式的可编辑情况、已完成的检查，以及尚存的源文疑点或环境限制。只有实际测得时才报告页数和图表数量。默认不交付内部 JSON、审计日志、逐页截图或工作脚本。

本技能包含的规则和排版工具是可复用基础，不承诺任何长度、领域或扫描质量的论文都无需人工复核。用户明确要求的语言、样式、范围和编辑方式优先于上述默认值。
