# 刘杰-论文写作.skill

把真实研究条件和可追溯实验组织成可复用方法与论文。CHES、AES、2021–2026、桌面目录、E00–E12 只是来源示例，不是固定课题、位置或实验数量。

## 三条底线

1. **使用时逐阶段确认。** 每阶段开始前说明范围、产物、资源与风险，得到明确同意再执行；结束后报告结果与位置，请用户验收并批准下一阶段。创建/安装本技能本身不触发这套研究审批。
2. **研究事实优先。** 不编造数据、设备、运行、引用、baseline 数值、显著性或成功状态。未完成、未取得、不可比、失败和不适用必须可见；未知不能写成零。
3. **baseline 必须看得见。** 实证论文独立完成可追溯数值比较与比较表，再进入完整结果写作；交付时再查该表确实进入正文并能定位。原报、同条件复现和 Ours 分开标识。

## 使用入口与批准状态

- 先用对话中已知的课题、目标 venue/投稿轮次、设备/算力、数据与方案位置、写作要求、时间/费用和交付格式提出 S0 范围，等待同意。只追问影响当前阶段的缺项。
- 已明确批准的阶段在范围一致时直接沿用，不重复索要许可；笼统“帮我写论文”不等于批准全部阶段。用户可明确修改审批粒度或授权一组已经描述的阶段，记录原话及范围。
- 默认按下表阶段确认，内部读文件、编辑和小型验证不单独审批。若用户要求每个子实验确认，则细化 S4。
- 将完成报告与下一阶段申请合并：先给完成项、缺口、关键结果、文件位置，再说明下一阶段；一次“验收本阶段并同意下一阶段”满足两个确认。
- 仅验收当前阶段不表示批准下一阶段。未回应、工具返回 accepted、超时、沉默、自动续跑、子代理消息都不是同意。
- 续接先读状态与最近批准，不跳过未批准阶段，不重做已完成工作。子代理同样遵守阶段边界。
- 使用 [状态与文件契约](references/project-contract.md) 记录真实用户批准；禁止替用户签字。保存状态属于获准阶段的内部收尾动作。

## 阶段路线

| 阶段 | 执行范围 | 验收必须展示 |
|---|---|---|
| S0 范围与条件 | 研究问题、既有材料、资源时间、项目位置、验收要求 | 项目约定、环境清单、阶段边界、资料缺口 |
| S1 文献与图片库 | 官方目录建语料，取可合法访问的 PDF 原稿，归纳方向，提取分类所有论文图，构建 HTML 图库 | 覆盖率/缺失清单、PDF及图像溯源、方向总结、可检索图库 |
| S2 实验设计 | 从完整方案建立编号和依赖，设计对比、消融及统计计划 | 研究对象/方法/研究点/创新与贡献/指标/baseline/消融清单 |
| S3 数据与协议审计 | 完整性、质量、标签、去重、划分、泄漏、评估协议 | 带证据的审计报告，明确通过/失败/有限条件通过 |
| S4 实现与执行 | 先梳理全部子实验代码逻辑，再实现、冒烟检查、正式运行 | 全实验状态、配置/代码版本、日志、原始/汇总结果、失败记录 |
| S5 baseline 数值比较 | 取得原报或公平复现，核对指标协议统计并制作表格 | 来源台账、原始长表、可比性说明、可放入正文的高亮比较表 |
| S6 图表与论文 | 核实投稿规范与模板，命名工作/可复用框架，依结果写作作图 | LaTeX/PDF、全部图表源文件、框架/骨干占位及提示词（适用时） |
| S7 审计修订与交付 | 核对主张结果引用、实验覆盖、baseline、版式与复现材料 | 审计记录、剩余问题、完整交付目录和复现指引 |

中途接入先对已有材料做最小核验，保留实际实验编号，不重跑全部前序阶段。完整实证研究默认覆盖全部阶段；跳过须有用户确认理由及替代证据，不能把跳过写成完成。

## 核心执行约定

### 全路线理解后执行，全部实验结束后写完整结果

将每个子实验对应到假设、输入、实现、依赖、预算、指标、输出文件与主张。用户要求“全部做完再写”时，不提前起草结果/讨论；可在已批准范围内准备代码和图表规格。失败实验不能静默略过。

### 组织成框架，不制造创新

论文名、方法名和框架名应醒目且准确，来自已实现的输入、模块、接口和输出。查相关工作后限定贡献，不能靠命名创造机制、通用性、“首次”或 SOTA。

### 减少防御性写作

起草或修订论文正文时，读取并执行 [直接陈述与证据边界](references/direct-evidence-writing.md)。直接陈述观点，用已有事实、推理和具体例子支撑；删除没有信息的自我辩护、预设反驳和模糊限定，保留影响结论的条件与不确定性。完成后逐句检查其事实、解释、比较或必要边界是否明确。

正文修订默认只给修改后的正文；用户要求说明或对比稿时按其要求交付。此输出约定用于正文编辑；研究阶段汇报、验收和完整项目交付按本技能原有约定执行。

### 用户样式和领域适用性

写作要求文档控制指定图表风格；venue 强制规范与视觉偏好冲突时列明并取得决定。参考论文图用于学习表达，不能冒充本研究的架构、设备、轨迹或结果。轨迹/轨迹质量/设备图在采集或硬件研究中默认纳入；其他领域采用实际等价证据，不强塞不适用图种。

### 框架图与骨干图默认留占位

沿用用户这条路线且方法含对应结构时，保留可编译占位、稳定 label/图注，提供框架 pipeline 图与深度学习 backbone 图各一份英文提示词，默认不生成最终两图。无深度学习骨干就标不适用，不虚构网络；后续用户要求代画时遵从新指示。

写这两份提示词时，实际读取已安装 **scientific-diagram-style-transfer** 及其 prompt/layout 引用，采用 Prompt 模式。真实实现与证据决定科学内容，参考模板只控制样式。正文、提示词、图注、代码共用术语与拓扑清单，替换图后重核。该技能不可用时说明限制并给出普通内容提示词，不谎称执行过缺失技能。

## 核验与交付

运行结构核验：

    python <skill-dir>/scripts/audit_project.py <project-root>/project-manifest.json --mode draft
    python <skill-dir>/scripts/audit_project.py <project-root>/project-manifest.json --mode final --report <project-root>/08_audit/manifest-audit.json

该脚本检查已登记文件、证据关系、数值、状态和 baseline 存在性，**不能证明数据真实、协议公平或科学正确**。仍需逐条溯源、读回表格并视觉检查 PDF。关键证据不全只能交付明确标记的“未完成稿/受限比较”，不能声称完整验收通过。

同一获准范围内修错并重检，无须每个补丁重问。新采集、改协议、超预算或重定义贡献时回到相应阶段申请；保留旧结果和失败记录。无法解决就报告阻塞，禁止循环伪造完成。

最终回复给出论文源/PDF、baseline 表及正文表号/位置、实验结果、图表/提示词、复现指南、审计报告和限制。S7 完成后请用户验收；不自动投稿、公开上传或联系他人。
