# S2–S5：实验、数据与 baseline

## S2：设备条件下的完整实验计划

读完用户路线与设备资料。记录实际可访问的 CPU/GPU/内存/存储、软件版本、采集硬件/传感器/固件、权限、时间/费用及并发限制；不能凭课题名猜设备规格。已有资料能回答的缺项不反复问。

每个子实验一行，保留原编号与顺序，E00–E12 仅是例子：

| 字段 | 要求 |
|---|---|
| 编号、依赖 | 映射原方案，说明前置实验 |
| 研究对象、问题 | 数据/系统/设备/人群及待检验假设 |
| 研究方法、实现 | 算法模块、代码入口、输入输出与配置 |
| 研究点、创新点、贡献概述 | 与已知工作差异及所需证据；未验证的标“待检验” |
| 评价指标 | 定义、单位、优劣方向、聚合与不确定性 |
| 可对比论文 | 真实可查来源、数据/代码可用性、协议差异 |
| 对照与消融 | 移除/替代/控制何因素，其余条件如何固定 |
| 划分、重复与统计 | train/validation/test、独立单位、种子/批次、区间或检验 |
| 预算与可行性 | 实际时间、内存/显存、采集量、费用 |
| 完成判据、产物 | 预期文件、对应图表与主张，不预填期望数值 |

建立依赖图及“贡献→实验→指标→图表”映射。按主张覆盖有效性、baseline、消融、鲁棒性、成本/效率、泛化及失败案例中适用项，不机械堆实验。资源不足时提出缩小问题、延期或替代实验由用户选，不虚构算力。

## S3：数据和协议审计

- 文件可读性、shape/dtype、条数/ID/单位、时间轴/采样率、标签对应、缺失/NaN/Inf、异常、重复、截断、压缩错误。
- 原始到派生数据的对应、哈希、预处理配置；原始数据不覆盖，修复输出另存。
- 样本和实体/设备/受试者/批次/时间层面的 train/validation/test 泄漏及近重复；归一化、特征筛选、阈值/调参仅用允许的数据。
- 分布、类别、条件覆盖及采集偏差；时序/功耗/电磁轨迹还检查饱和、触发/对齐、漂移、噪声、质量等适用因素。
- 样本量、独立重复单位和统计方法对拟议结论是否足够。相关轨迹、同一个体重复记录、不同种子不自动构成完全独立样本。
- 保存每项检查的代码/命令、判据、实际结果、受影响记录和处理；修改后复核并保留前后清单。

严重泄漏、损坏、标签错误或不可追溯时阻止正式跑批。有限条件通过要写明限制、不可作的结论并获批准；“没报错”不是无问题证明。

## S4：理解全部实验，再实现与执行

1. 为全路线建立实现计划：已实现/待实现/依赖缺失、公式、输入输出、预算。保持与用户方案逐项对应。
2. 固定代码版本/源文件哈希、环境依赖、数据版本/划分、种子、配置、设备与测量口径；记录确定性开关和限制。
3. 小批量检查 shape/核心逻辑/端到端，再正式跑。冒烟和合成结果单独标识，不能写进真实实验表。
4. 按依赖执行；每次保存 run_id、命令、起止时间、退出码、日志、资源、进度和可恢复检查点。仅写了脚本不算跑完。
5. 保留逐次原始测量/预测、必要模型产物、指标计算脚本与汇总；保存所有运行及排除原因，不只保留最佳种子。报告均值/变异或合适区间。
6. 验证集调参后锁定最终测试协议；不能用测试集反复选模型仍称独立测试。
7. 完成矩阵逐个标 succeeded/failed/blocked/not_run/excluded；excluded 有方法学理由与批准。用户要求全跑时，未完成不能进入“全部结果已完成”的写作。

## S5：独立完成 baseline 数值比较

### 取数与复现

- 先从正式论文/附录、官方代码、作者公开结果找相同任务的数值；核实版本、页码、表/图行列或仓库版本。不能拼搜索摘要生成数字。
- 每值记录 paper_id、venue/year、指标/value/unit/direction、数据集版本/划分、训练调参预算、设备/威胁模型、样本量、重复统计、来源类型和定位。
- 来源类型：reported（论文原报）、reproduced（实际复现）、ours（本工作实测）、estimated_from_figure（用户同意后从图读数估计）。估计带误差/精度，不能冒充原报精确数值。
- 复现保存命令、环境、版本、配置、原始结果与差异；其他人结果不能改成 Ours。
- 同名指标也需核对定义/单位/数据/划分/样本量/预算/统计。不同协议分组，不同硬件的时延能耗尤其不能直接判胜。
- 缺关键 baseline 时先报告可行选项：许可范围内复现、替换合理论文、保留明确缺失；联系作者需另行授权。缺比较不能宣称 SOTA 或完成数值比较。

### 必交比较表

同时输出完整精度长表 CSV/JSON、便于阅读的 HTML/Markdown 及正文 LaTeX 表。正文明确引用并解释可比性和限制。

默认按用户要求：**行标签为“论文期刊/会议（含年份）、指标（含 ↑/↓）”，列标签为各篇 baseline 论文简称和 Ours**。添加必要的数据集/协议/单位分组；多 venue/多数据集时分表或分面，避免假对齐。改变主轴须说明并获同意。

- 最优判定使用原始精度及正确的 max/min 方向，仅限同指标同可比组。
- 最优数值同时**加粗、高亮**，真实并列全部标。显示四舍五入不等于真实并列；有混淆时增加精度/脚注。
- venue 禁彩色底纹时用合规浅灰/非颜色强调，并保留粗体表注。
- 原报/复现/估计明显区分。不可比、未报告、未运行用有说明的破折号/NR/Not run，不填 0。
- 只有 Ours 有值或协议不可比时不标“最优/胜出”，显示缺口。
- 数值更优不自动显著；提供重复、不确定性与适当检验，不仅突出最好看的种子。

### 验收与后续定位

实际读回表，检查双方数值、来源、单位、方向、最优和缺失标记、可比组。给出文件路径、候选正文表号，保存 baseline_sources.csv 和原始长表并登记清单。论文修改时同步，最终再次检查 PDF 中确实存在这张表。
